# سامانه هوشمند نوسان‌گیری رمزارز — نوبیتکس ۷٫۴٫۲

این بسته برای انتشار مستقیم در **GitHub Pages** آماده شده است. ساختار ZIP تخت است؛ پس از استخراج، فایل‌ها را مستقیماً در ریشه مخزن GitHub قرار دهید.

## محتوای بسته

- `index.html` — نسخه ۷٫۴٫۲ برنامه، شامل اسکن تدریجی ۱۵۰ بازار، تحلیل چندتایم‌فریمی، واچ‌لیست و هشدار صوتی بهبود شاخص‌های شش‌گانه.
- `nobitex-account.js` — ماژول اتصال خواندنی حساب نوبیتکس برای نمایش اطلاعات حساب.
- `native-bridge.js` — fallback وب؛ پل کامل بومی Android در این بسته GitHub Pages قرار ندارد.
- `manifest.webmanifest`، `sw.js` و آیکون‌ها — فایل‌های PWA و کش پوسته برنامه.
- `CHANGELOG-FA.md` و `VERSION.txt` — سابقه تغییرات و شماره نسخه.
- `.nojekyll` — جلوگیری از پردازش ناخواسته فایل‌ها توسط Jekyll.

## بارگذاری در GitHub Pages

۱. ZIP را استخراج کنید.
۲. **تمام فایل‌های داخل پوشه استخراج‌شده**، از جمله `index.html` و فایل `.nojekyll` را در ریشه یک مخزن GitHub بارگذاری کنید؛ پوشه واسط را داخل مخزن قرار ندهید.
۳. در مخزن به مسیر **Settings → Pages** بروید.
۴. در بخش **Build and deployment**، گزینه **Deploy from a branch** را انتخاب کنید.
۵. شاخه `main` و پوشه `/(root)` را انتخاب و ذخیره کنید.
۶. پس از انتشار، نشانی GitHub Pages را با HTTPS باز کنید.

## اسکن ۱۵۰ بازار

- سقف فهرست بازار ۱۵۰ نماد تتری است و هیچ‌یک از نمادها به‌علت فیلتر نمایشی از Universe اسکن حذف نمی‌شود.
- فیلتر سیگنال در شروع روی «همه» قرار دارد؛ فیلترهای دیگر می‌توانند فقط بخشی از نتایج را نمایش دهند.
- موتور تحلیل به‌صورت تدریجی و چرخشی کار می‌کند؛ اولویت پردازش با حجم معاملات ۲۴ساعته است و نمادها در سه سطح ۵۰تایی رسیدگی می‌شوند.
- اسکن هم‌زمان ۱۵۰ ارز انجام نمی‌شود. سرعت تکمیل هر دور به پاسخ API، کیفیت اتصال و محدودیت نرخ درخواست بستگی دارد.
- در بخش وضعیت، تعداد کل بازار هدف، تعداد تحلیل‌شده، جایگاه بعدی اسکن و نرخ تکمیل اخیر قابل مشاهده است.

## هشدار صوتی واچ‌لیست

- ارزها را به واچ‌لیست اضافه کنید و دکمه «صدا خاموش» را یک‌بار فعال کنید.
- با بهترشدن هر یک از شش شاخص لانگ در ارزهای واچ‌لیست، سامانه هشدار صوتی می‌دهد؛ اولین تحلیل صرفاً مبنای مقایسه را ثبت می‌کند.
- هشدار به‌تنهایی سیگنال قطعی خرید نیست.
- مرورگر ممکن است پخش صدا یا اجرای اسکن را در حالت پس‌زمینه یا پس از بسته‌شدن صفحه متوقف کند. برای هشدار پایدار در حالت بسته، زیرساخت Push سمت سرور لازم است.

## اتصال API حساب

- ماژول اتصال حساب در بسته حفظ شده و صرفاً برای دسترسی خواندنی طراحی شده است.
- برای امنیت حساب، در پنل نوبیتکس فقط مجوز `READ` را فعال کنید؛ مجوز معامله و برداشت را فعال نکنید.
- کلیدهای API را در کد، README، مخزن GitHub یا فایل‌های قابل انتشار قرار ندهید؛ آن‌ها را فقط در رابط محلی برنامه وارد کنید.
- اتصال مستقیم مرورگر به API به HTTPS، پشتیبانی CORS از سوی سرویس و دسترسی شبکه نیاز دارد. فعال بودن ماژول به معنای تضمین اتصال در همه شبکه‌ها نیست.

## PWA و کش

- Service Worker فقط فایل‌های محلی پوسته برنامه را کش می‌کند؛ درخواست‌های API و بازار خارجی را کش یا شبیه‌سازی نمی‌کند.
- نام کش به نسخه ۷٫۴٫۲ تغییر کرده تا فایل‌های پوسته نسخه قبلی با نسخه جدید مخلوط نشوند.
- نصب PWA و Service Worker روی GitHub Pages از طریق HTTPS فعال می‌شوند؛ بازکردن مستقیم فایل با `file://` این قابلیت‌ها را فعال نمی‌کند.

## محدوده و آزمون

این بسته برای GitHub Pages است، نه سورس کامل Capacitor و نه APK آماده نصب. اجرای سفارش خودکار انجام نمی‌شود. تحلیل‌ها ابزار پایش و تصمیم‌یار هستند، توصیه قطعی سرمایه‌گذاری یا تضمین سود نیستند. آزمون نحوی اسکریپت‌ها و سلامت ZIP انجام می‌شود؛ آزمون زنده نرخ پاسخ و اتصال API نوبیتکس در این محیط انجام نشده است.


## رفع خطای نیازمندی Node.js در ساخت Android

Capacitor 8 به Node.js نسخه 22 یا بالاتر نیاز دارد. این مخزن با فایل `.nvmrc` روی شاخه 22 تنظیم شده و Workflow گیت‌هاب نیز پیش از اجرای Capacitor نسخه Node را کنترل می‌کند.

### ساخت محلی در Windows (PowerShell)

1. نسخه LTS شاخه 22 یا بالاتر Node.js را نصب کنید: https://nodejs.org/
2. تمام پنجره‌های ترمینال را ببندید و یک PowerShell جدید باز کنید.
3. نسخه فعال را کنترل کنید: `node -v`؛ خروجی باید `v22.x.x` یا بالاتر باشد.
4. در ریشه پروژه اجرا کنید: `npm install`
5. کنترل نیازمندی: `npm run check:node`
6. افزودن پلتفرم Android: `npx cap add android`
7. همگام‌سازی: `npx cap sync android`

اگر هنوز نسخه قدیمی نمایش داده می‌شود، مسیر نصب Node را در PATH ویندوز اصلاح کنید و ترمینال یا محیط توسعه (VS Code) را کاملاً دوباره باز کنید. نصب Node.js جدید به‌تنهایی، فرایندهای ترمینال باز را به‌روزرسانی نمی‌کند.

### ساخت در GitHub Actions

Workflow موجود در `.github/workflows/android.yml` از `actions/setup-node@v4` با `node-version: '22'` استفاده می‌کند. برای اجرای آن، آخرین محتوای ZIP را در ریشه مخزن بارگذاری کنید و از تب Actions، Workflow با عنوان **Build Android APK** را اجرا کنید. فایل APK خروجی در بخش Artifacts همان اجرای موفق قابل دریافت خواهد بود.


## رفع خطای Node.js در GitHub Actions

این نسخه، Node.js را در Workflow روی نسخه `22.21.1` قفل می‌کند و پیش از نصب وابستگی‌ها و نیز بلافاصله پیش از اجرای `npx cap add android` نسخه و مسیر اجرایی Node را کنترل می‌کند.

**نکته مهم:** همه محتویات این بسته را در ریشه مخزن GitHub جایگزین کنید؛ به‌ویژه فایل مخفی `.github/workflows/android.yml` و فایل `.nvmrc`. اگر در مخزن Workflow قدیمی دیگری برای ساخت Android وجود دارد، اجرای دستی را از تب Actions روی Workflow با نام **Build Android APK** انجام دهید و Workflow قدیمی را غیرفعال کنید. در لاگ اجرای جدید باید مرحله `Set up Node.js 22.21.1` و سپس `Diagnose and enforce Node.js version` دیده شود. اگر این دو مرحله دیده نمی‌شوند، هنوز Workflow جدید اجرا نمی‌شود.

## رفع اشکال اجباری Node.js 22 در GitHub Actions

برای جلوگیری از اجرای ناخواسته Workflow قدیمی، فایل مستقل زیر نیز اضافه شده است:

`.github/workflows/android-node22-forced.yml`

پس از Commit و Push فایل‌ها به شاخه `main`، در GitHub وارد تب Actions شوید و Workflow با نام **ANDROID APK - FORCE NODE 22** را انتخاب و از گزینه **Run workflow** اجرا کنید. این Workflow فقط با اجرای دستی فعال می‌شود و در گزارش آن باید دو بخش `PROOF - verify the active Node runtime` و `Add Android platform using verified Node` دیده شود. در خروجی بخش اول باید `v22.21.1` ثبت شود.

اگر این Workflow در تب Actions دیده نمی‌شود، فایل در مسیر دقیق `.github/workflows/android-node22-forced.yml` در شاخه پیش‌فرض مخزن Commit نشده است.
