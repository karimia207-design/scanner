# سامانه هوشمند نوسان‌گیری نوبیتکس ۷٫۶٫۰

این بسته، سورس نسخه وب و پوسته Android مبتنی بر Capacitor را در یک پروژه نگه می‌دارد. چارچوب معاملات نقدی (Spot)، شروط ورود و خروج، مدیریت ریسک، واچ‌لیست، پایش پس‌زمینه و اصل «بدون سفارش‌گذاری خودکار» حفظ شده‌اند. تغییرات این نسخه بر اعتبار Snapshot، تثبیت وضعیت، آزمون تاریخی، امنیت امضا و پایداری Build متمرکز است.

## تغییرات این نسخه

- محاسبه واحد `risk` برای ورود، حد ضرر، هدف، سقف ساختاری، اسپرد و R/R خالص؛ جدول، مودال و دفتر معاملات از همان Snapshot استفاده می‌کنند.
- هر Snapshot شناسه مستقل دارد و در جدول اصلی، مودال، واچ‌لیست، ژورنال و Diagnostics ثبت می‌شود.
- با تغییر مظنه، اسپرد، هزینه خروج و R/R خالص دوباره محاسبه می‌شوند. ورود به وضعیت آماده باید روی دو مظنه تازه و با حداقل فاصله ۶ ثانیه روی همان کندل‌های بسته‌شده پایدار بماند؛ نقض یک شرط سخت، وضعیت را بی‌درنگ از آماده خارج می‌کند.
- شمارنده تایم‌فریم اصلی فقط ۱H و ۴H را از ۲ نشان می‌دهد. هم‌ترازی با زمان بسته‌شدن کندل‌ها کنترل می‌شود.
- سقف سن برای واگرایی افزوده شده است؛ پنجره مجاز بر حسب تایم‌فریم در کد تعریف شده.
- فرض کارمزد، لغزش و حداقل حجم هنوز ۰٫۱٪ هر سمت، ۰٫۱۵٪ لغزش هر سمت و ۱۰٬۰۰۰ USDT حجم روزانه است. کاربر باید آن‌ها را با حساب واقعی تطبیق دهد و تأیید کند؛ تا آن زمان آلارم ورود نهایی فعال نمی‌شود. این مقادیر عمداً خودسرانه تغییر نکرده‌اند.
- بک‌تست تک‌نماد، حد ضرر یک‌ساعته را با حد ضرر چهارساعته مقایسه می‌کند. برای گپ زیر حد ضرر، قیمت پرشدن بدترِ Open کندل یا Stop استفاده می‌شود؛ اگر حد ضرر و هدف در یک کندل لمس شوند، حد ضرر مقدم فرض می‌شود.
- آزمون پرتفوی چندنمادی تا ۱۲ نماد دارای داده محلی را با سقف ۳ موقعیت هم‌زمان و تقسیم بودجه ریسک میان موقعیت‌ها بررسی می‌کند. Win Rate، Profit Factor، Maximum Drawdown، Expectancy و P/L گزارش می‌شوند.
- بک‌تست در هر ۱۶ کندل به صف رویداد واگذار می‌کند تا رابط فرصت به‌روزرسانی داشته باشد.
- آزمون تطبیق داخلی ۱۳ سری اندیکاتور را با پیاده‌سازی مستقل بررسی می‌کند. چهار بردار RSI شامل سه رفتار مرزی مستندشده در منبع TA-Lib و یک دنباله بازگشتی Wilder نیز آزموده می‌شوند؛ این پوشش معادل اعتبارسنجی تمام اندیکاتورها با TA-Lib یا TradingView نیست.
- امضای Ed25519 اندروید در لایه Native انجام می‌شود. کلید خصوصی در عملیات امضا به JavaScript برگردانده نمی‌شود و درخواست محدود به `GET /users/wallets/list` است.
- Retry و backOff خطای ۴۲۹ در صف مشترک انجام می‌شوند؛ فاصله پایه OHLC برابر ۱۶۰۰ms است و محدودیت تطبیقی می‌تواند آن را افزایش دهد.
- Actionهای GitHub با SHA ثابت فراخوانی می‌شوند. این بسته فقط APK نوع Debug می‌سازد و هیچ Secret یا keystore کاربری لازم ندارد؛ Gradle از debug keystore موقت Runner استفاده می‌کند.
- افزودن دستی هر بازار USDT فعال نوبیتکس به واچ‌لیست و افزودن دسته‌جمعی نتایج فیلتر فراهم است. Back اندروید ابتدا لایه باز را می‌بندد و در صفحه ریشه باعث خروج برنامه نمی‌شود.

## نصب و Build وب

محتویات پوشه `web/` را در ریشه GitHub Pages بارگذاری کنید. صفحه `index.html` نسخه دسکتاپ و `mobile-index.html` نسخه موبایل است. برای استفاده از پروکسی اختصاصی، Origin دقیق آن باید به `connect-src` در CSP هر دو صفحه افزوده شود.

## تولید APK بدون رمز یا Secret

این بسته برای ساده‌سازی Build، فقط APK نوع Debug تولید می‌کند. هیچ Secret، گذرواژه، فایل keystore یا تنظیمی در GitHub لازم نیست. پس از بارگذاری تمام محتویات ZIP در ریشه Repository و Commit روی شاخه `main` یا `master`، فایل `.github/workflows/build-android.yml` باید شناسایی شود و Workflow با Push به‌طور خودکار APK را می‌سازد. همچنین می‌توان از زبانه Actions گزینه `Build Nobitex Android APK` را با `Run workflow` به‌صورت دستی اجرا کرد. فقط همین Workflow را نگه دارید؛ فایل‌های Workflow آزمایشی یا تکراری را از `.github/workflows/` حذف کنید.

Artifact خروجی با نام `nobitex-v7.6.0-android-debug-apk` ارائه می‌شود و فایل آن `app-debug.apk` است. Gradle آن را با debug key موقت همان Runner امضا می‌کند.

**محدودیت امضای Debug:** کلید Debug روی Runnerهای GitHub پایدار نیست. برای نصب نخست، ممکن است لازم باشد نسخه قبلی برنامه را حذف کنید. در Buildهای بعدی نیز اگر کلید Debug تغییر کرده باشد، نصب به‌روزرسانی روی APK قبلی پذیرفته نمی‌شود و باید نسخه قبلی حذف و APK جدید نصب شود. حذف برنامه ممکن است داده‌های محلی، تنظیمات و کلیدهای API ذخیره‌شده در برنامه را پاک کند. از ژورنال معاملات و اطلاعات لازم برای اتصال مجدد پشتیبان بگیرید.

این بسته برای تولید APK آزمایشی و نصب اولیه است. اجرای `npm run validate` اکنون با مسیر Debug بدون Secret سازگار است و دیگر وجود گردش‌کار Release امضاشده را مطالبه نمی‌کند. اگر بعداً بخواهید نسخه‌های Release را بدون حذف نسخه قبلی نصب کنید، باید جداگانه keystore پایدار تعریف شود؛ آن روش نیازمند Secretهای امضاست و در این راهنما استفاده نمی‌شود.

### Lockfile و نصب بازتولیدپذیر

به‌علت نبود دسترسی به npm registry در محیط آماده‌سازی، `package-lock.json` در این ZIP تولید نشده است و از ساختگی‌کردن lockfile خودداری شده. اجرای نخست GitHub Actions یک lockfile بر اساس نسخه‌های مستقیم دقیق `package.json` ایجاد می‌کند، سپس `npm ci` را اجرا و lockfile را به‌عنوان Artifact با نام `nobitex-v7.6.0-dependency-lockfile` بارگذاری می‌کند. آن را از Artifacts دریافت و در ریشه Repository Commit کنید؛ اجراهای بعدی با همان lockfile و `npm ci` انجام می‌شوند. اجرای نخست هنوز مرحله حل وابستگی دارد و کاملاً lockfile-pinned نیست.

## بک‌تست: دامنه و محدودیت‌ها

- بک‌تست هر نماد به تاریخچه محلی همان نماد وابسته است؛ معمولاً نزدیک به ۵۰۰ کندل ۱H و حدود ۲۰ روز. ابزار پرتفوی حداکثر ۱۲ نماد دارای حداقل داده را جمع می‌کند، اما تاریخچه مشترک و بلندمدت تضمین نمی‌شود.
- ورود روی Open کندل یک‌ساعته بعد از سیگنال شبیه‌سازی می‌شود. ماشه مستقل ۵m/۱۵m در تاریخچه بازسازی نمی‌شود؛ اسپرد تاریخی از دفتر سفارش موجود نیست و برابر سقف اسپرد تنظیم‌شده فرض می‌شود؛ لغزش متغیر، عمق دفتر، صف واقعی اجرا و آزمون خارج از نمونه نیز مدل نشده‌اند.
- برای پرتفوی حداکثر سه موقعیت هم‌زمان فرض می‌شود و بودجه ریسک بین آن‌ها تقسیم می‌شود. خروجی تعداد نمادهای واقعاً معامله‌شده، تعداد معاملات، موقعیت‌های ردشده به علت سقف هم‌زمانی و شاخص‌های عملکرد را نشان می‌دهد.
- هیچ Win Rate یا Expectancy واقعی از پیش درج نشده است. آزمون واحد و تاریخچه کوتاه محلی، اثبات سودآوری یا تخمین قابل اتکای نرخ برد آینده نیست.
- بک‌تست تاریخی از ترد اصلی به‌صورت مرحله‌ای yield می‌کند؛ این کار وقفه UI را کاهش می‌دهد اما آن را به Web Worker منتقل نمی‌کند.

## موارد عمداً حل‌نشده / نیازمند آزمون دستگاه

- سرویس Foreground اندروید همچنان اعلان، WakeLock و heartbeat را مدیریت می‌کند؛ موتور تحلیل در WebView است و سرویس Native مستقلاً شبکه و اسکن را اجرا نمی‌کند. Doze یا توقف WebView می‌تواند تحلیل را متوقف کند؛ آزمون چندساعته روی گوشی واقعی لازم است.
- `app.js` هنوز یک IIFE بزرگ است و در این نسخه ماژول‌بندی کامل نشده؛ بازنویسی ساختاری در کنار اصلاح منطق ریسک، ریسک رگرسیون غیرضروری داشت.
- جدول اصلی همچنان برای نمایش کامل ستون‌ها عرض حداقلی بزرگ دارد. نسخه موبایل کارت‌های بیشتری نشان می‌دهد، اما بازطراحی کامل جدول ۲۰ ستونی در این نسخه انجام نشده است.
- فونت فارسی درون بسته نشده؛ stack سیستم با اولویت Vazirmatn/Noto و سپس فونت‌های پیش‌فرض سیستم استفاده می‌شود. روی دستگاهی که Vazirmatn نصب ندارد، ظاهر فونت به فونت سیستمی بستگی دارد.
- CSP اتصال را به مبدأهای نوبیتکس، CoinGecko و WebSocket نوبیتکس محدود کرده؛ `style-src 'unsafe-inline'` به‌علت سبک‌های پویا هنوز باقی است. پروکسی اختصاصی نیازمند افزودن Origin دقیق است.
- ساخت Gradle، امضای واقعی با keystore کاربر، نصب روی Samsung A37، آزمون زنده API و پایش چندساعته Doze در این محیط اجرا نشده‌اند.

## اصول معامله و API

اتصال API حساب فقط برای خواندن موجودی است؛ هیچ سفارش، برداشت یا معامله‌ای ارسال نمی‌شود. مجوز API را فقط روی READ قرار دهید. تنظیمات کارمزد، لغزش و حجم باید متناسب با شرایط واقعی حساب کاربر تأیید شود.
